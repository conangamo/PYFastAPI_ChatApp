GHI CHÚ VIDEO CALL 1-1 (WebRTC với aiortc) – TÍCH HỢP VÀO DỰ ÁN PYFastAPI_ChatApp
================================================================================

Mục tiêu: Thêm chức năng gọi video 1-1 thời gian thực vào ứng dụng chat hiện tại.
Công nghệ chính:
  - WebRTC: aiortc (Python implementation)
  - Signaling: Mở rộng WebSocket hiện có (không dùng Firebase hay TCP riêng)
  - Camera: OpenCV để capture và hiển thị frame
  - UI: Flet (desktop app)
  - Backend: FastAPI + WebSocket manager hiện tại

================================================================================
1. KIẾN TRÚC TỔNG QUAN
================================================================================

- Signaling hoàn toàn qua WebSocket hiện tại (/api/ws/chat/{user_id})
  → Thêm các message type mới: call_invite, call_invite_sent, call_incoming,
     call_accept, call_accepted, call_reject, call_end,
     sdp_offer, sdp_answer, ice_candidate

- Backend (FastAPI):
  - Quản lý active_calls trong memory (dict trong websocket/manager.py)
    active_calls: dict[call_id: str, CallSession]
  - CallSession chứa: caller_uid, callee_uid, state ("ringing"|"active"|"ended")

- Frontend (Flet):
  - Thêm button "Video Call" trong header của conversation (chat_screen.py)
  - Tạo page mới: VideoCallPage (ft.View hoặc riêng ft.Page)
  - Hiển thị video local/remote bằng ft.Image (update src_base64 từ OpenCV frames)
  - Quản lý state cuộc gọi trong session hoặc class global:
    current_call_id, current_call_peer_id, current_call_is_caller

================================================================================
2. LUỒNG CUỘC GỌI CHI TIẾT
================================================================================

2.1 Caller (A) khởi tạo cuộc gọi tới Callee (B)

1. A nhấn button "Video Call":
   - Gửi qua WebSocket:
     {"type": "call_invite", "to_uid": B_uid}

2. Backend nhận message:
   - Tạo call_id = uuid4()
   - active_calls[call_id] = {"caller_uid": A_uid, "callee_uid": B_uid, "state": "ringing"}
   - Gửi lại cho A: {"type": "call_invite_sent", "call_id": call_id, "ok": true}
   - Gửi cho B (nếu B đang online): {"type": "call_incoming", "call_id": call_id, "from_uid": A_uid}

3. Client A nhận "call_invite_sent":
   - Lưu current_call_id, current_call_peer_id = B_uid, is_caller = True
   - Bật ft.Timer(30_000 ms) để timeout ringing
   - Hiển thị overlay "Đang gọi..." trong chat window

4. Client B nhận "call_incoming":
   - Nếu current_call_id is None (không đang gọi):
        → Hiện ft.AlertDialog: "Cuộc gọi video từ {A_name}" với nút Accept / Reject
   - Nếu đang có current_call_id → Tự động reject (busy)

   - Nếu Accept:
        + Lưu current_call_id, current_call_peer_id = A_uid, is_caller = False
        + Gửi {"type": "call_accept", "call_id": call_id}
        + Mở VideoCallPage và gọi start_webrtc_connection()

   - Nếu Reject:
        + Gửi {"type": "call_reject", "call_id": call_id, "reason": "rejected" hoặc "busy"}

5. Backend nhận "call_accept":
   - Cập nhật active_calls[call_id]["state"] = "active"
   - Gửi cho A: {"type": "call_accepted", "call_id": call_id}
   - Gửi cho B: {"type": "call_accept_ok", "ok": true}

6. Client A nhận "call_accepted":
   - Dừng timer 30s
   - Mở VideoCallPage(is_caller=True) và gọi start_webrtc_connection()

2.2 Signaling SDP & ICE (sau khi cả hai bên đã mở VideoCallPage)

- Cả hai bên tạo RTCPeerConnection với STUN:
  config = RTCConfiguration(iceServers=[RTCIceServer(urls="stun:stun.l.google.com:19302")])
  pc = RTCPeerConnection(configuration=config)

- Caller (is_caller=True):
  1. pc.createOffer() → offer
  2. await pc.setLocalDescription(offer)
  3. Gửi WebSocket: {"type": "sdp_offer", "call_id": call_id, "sdp": offer.sdp, "sdp_type": "offer"}

- Callee (is_caller=False):
  1. Lắng nghe message "sdp_offer"
  2. await pc.setRemoteDescription(RTCSessionDescription(sdp=offer_sdp, type="offer"))
  3. answer = await pc.createAnswer()
  4. await pc.setLocalDescription(answer)
  5. Gửi {"type": "sdp_answer", "call_id": call_id, "sdp": answer.sdp, "sdp_type": "answer"}

- ICE candidates:
  @pc.on("icecandidate")
  def on_icecandidate(candidate):
      if candidate:
          gửi {"type": "ice_candidate", "call_id": call_id, "candidate": candidate.to_json()}

  Khi nhận "ice_candidate" từ peer → await pc.addIceCandidate(RTCIceCandidate(**data))

================================================================================
3. LƯU Ý QUAN TRỌNG ĐỂ ỔN ĐỊNH & KHÔNG CRASH (Flet + asyncio)
================================================================================

3.1 UI & Async
- Flet chạy single-thread asyncio → KHÔNG block page.update()
- Chạy tất cả aiortc coroutines bằng asyncio.create_task()
- Update video frame: ft.Image(src_base64=base64_frame) → page.update()

3.2 Camera OpenCV
- Trong VideoCallPage.on_mount():
  cap = cv2.VideoCapture(0)
  timer = ft.Timer(33ms)  # ~30fps
  def read_frame():
      ret, frame = cap.read()
      if ret:
          _, buffer = cv2.imencode('.jpg', frame)
          base64_frame = base64.b64encode(buffer).decode()
          local_video.src_base64 = base64_frame
          page.update()
  timer.callback = read_frame
  timer.start()

- Trong on_dismiss / close:
  timer.cancel()
  if cap.isOpened(): cap.release()

3.3 Đóng RTCPeerConnection an toàn
- Trong cleanup của VideoCallPage:
  if pc and pc.connectionState != "closed":
      asyncio.create_task(pc.close())

3.4 Xử lý Call Collision & Busy
- Khi nhận "call_incoming" mà current_call_id != None → tự động gửi "call_reject" reason="busy"
- Khi nhận "call_reject":
  if reason == "busy": hiển thị "Người dùng đang bận"
  else: "Người dùng đã từ chối"

3.5 Timeout
- Ringing timeout: Caller dùng ft.Timer(30s)
  → Nếu hết thời gian chưa có accept → gửi "call_end" + hiển thị "Không ai bắt máy"
- SDP/ICE timeout: Đặt giới hạn chờ 20s (có thể dùng asyncio.wait_for)

3.6 Dọn dẹp sau cuộc gọi
- Khi một bên nhấn "End Call":
  - Gửi {"type": "call_end", "call_id": call_id}
  - Đóng pc, release camera, xóa current_call_id
- Backend nhận "call_end" → xóa active_calls[call_id] và forward message cho peer
